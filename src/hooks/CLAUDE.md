# src/hooks/ — shared hooks

- `useDocumentTitle(title)` — sets `"<title> — Impact List"`; no-ops on falsy (so detail pages can pass `entity?.name` while loading and NotFound owns the 404 title). Every page uses it.
- `useNameSearch(items)` — list-page search state: returns `{searchTerm, setSearchTerm, filteredItems}` filtering by `name` (case-insensitive, query trimmed). `filteredItems` is memoized per term — safe to pass straight to SortableTable. Used by DonorList and RecipientList.
- `useCategoryChartData(combinedAssumptions, donations, {maxCategories})` — memoized per-category aggregation (donation amount + lives saved per category) behind the donor/recipient detail charts; collapses the tail into an "Other Causes" row past `maxCategories`. Pass real donations only (no synthesized "unknown" rows).
- `useChartViewTransition(rawChartData)` — the detail charts' donations⇄lives-saved toggle state machine. The chart renders `valueTarget` with recharts animation; a toggle animates by holding the FROM value and retargeting, then rows rebuild once idle. Returns `{chartData, chartView, isTransitioning, handleChartViewChange}`.
- `useFormattedNumberInput(value, emitChange)` — the formatted-number input core (local display state, comma formatting, cursor preservation, prop→display sync) behind CurrencyInput/NumericInput; `emitChange(formatted, raw)` leaves parsing to the component.
- `useDismissibleMenu` — outside-click + Escape dismissal for popovers/menus; use it instead of hand-rolling listeners. `onDismiss` receives the reason (`'outside' | 'escape'`) so callers can refocus the trigger on Escape (Header and AssumptionsDropdown do).
- `useAssumptionsLibrary` — the saved-assumptions library state machine shared by AssumptionsPage and AssumptionsSelector: entries (curated + saved), value-derived active entry reconciliation, fingerprint-based unsaved-changes detection, the change-event subscription, and the load/confirm/replace flow (callers render the confirmation modal from `pendingLoadEntry`). When current normalized values match default or any library entry, that identity becomes active automatically; duplicate matches keep the already-active entry, then fall back to library order. `notifyOnEntrySwitch` adds the page's informational notices. Mocks of `markSavedAssumptionsLoaded` must return `{ ok }` — the hook checks it.
- `useAssumptionsEditorController` — the assumptions editor's tab/entity/URL orchestration (unknown ids from stale links resolve to null, not editors).
- `useUnsavedChangesReporter(hasUnsavedChanges, onChange)` — reports a dirty flag to a parent callback and reports `false` on unmount, so a parent can never be left holding a stale "dirty" flag after the reporting component (e.g. a drill-in effect editor) is closed by a navigation. Used by the three effect editors and AssumptionsEditor's page reporting.
- `useAssumptionsShareActions` / `useSaveAssumptionsModal` — share-link and save-to-library flows shared by AssumptionsPage and AssumptionsSelector.
- `useAssumptionsSelectorPreference` — localStorage-backed "show selector on every page" preference.
- `useRecipientEffectsDraft` — the recipient effect editors' entire draft state machine (stringly override drafts, override/multiplier exclusivity, validation errors, preview costs, save shape via `getEffectsToSave()` — drafts carry an internal `_baseEffect` that must never reach saved state). Saved override objects carry the recipient's default overrides forward, NOT just the edited fields: user overrides replace the default set wholesale at combine time, so a fields-only-diff would silently revert untouched default-override fields to category values. Draft re-initialization is VALUE-gated on `getBaselineReinitSignature` (assumption updates deep-copy, so identity can't detect real changes) — unrelated assumption changes must not wipe in-progress edits. That signature deliberately INCLUDES the internal `_baseEffect` (unlike `getEffectsSignature`, which compares saved shapes): a cause-level revert changes the effective base while wrapper fields stay identical. Drafts initialize FROM the baseline (never `[]`), so a fresh mount never reports a false "dirty" frame — `hasUnsavedChanges` feeds the navigation guard and the Apply button. `CategoryEffectEditor` applies the same gate and initialization. Takes `defaultAssumptions`/`userAssumptions` as arguments (pure; unit-tested with synthetic data).
- `useRecipientEffectAdapter` — adapts recipient override/multiplier wrappers onto the category effect-input layouts.
- `useGlobalForm` — global-parameters form state for the editor. Rehydration is per-parameter and VALUE-aware (tracked via a last-hydrated ref): only parameters whose underlying value actually changed rehydrate, so un-applied drafts survive unrelated `userAssumptions` mutations (review-modal reverts, loading a set that doesn't touch them) — normalization deep-copies, so object identity can't be used to detect real changes. Also exposes `unappliedChangeCount` (the per-parameter dirty count; `hasUnsavedChanges` derives from it) and `discardDraft()` (resets the whole draft to the last-hydrated applied values and clears errors) — both feed the editor's draft-status indicators.
- `useAssumptionsForm.js` — **misnamed**: it actually exports `useRecipientSearch` (recipient search/filter state). Rename pending; don't add a real `useAssumptionsForm` without resolving the collision. Matches are memo-derived (never stale state) and name-sorted; with no term it lists only recipients with recipient-specific assumptions (built-in or user-edited). Search results cap at `DEFAULT_RESULTS_LIMIT` with `totalMatches`/`isTruncated` always reported and `handleShowAllMatches` to reveal everything — truncation is never silent, and a new term re-truncates.

Convention: hooks that subscribe to storage/events must clean up, and anything loading external assumption data must catch `normalizeUserAssumptions` incompatibility errors (see the `src/contexts/` context file).
